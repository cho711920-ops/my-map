# JS 매물 수집기 업그레이드 (2026-08-06)

## 운영 버전

- 네이버 수집기: `5.6.0`
- 당근 수집기: `1.3.0`
- 공실박스 수집기: `2.1.0`
- 통합 설치 주소: `https://js-map.com/collector-install.html`

## 실행 방식

`JS 매물 수집` 북마크 하나가 현재 사이트의 호스트를 확인하고 `js-map.com`에서 최신 수집기 파일을 매번 불러온다. 이전 Vercel 주소는 운영 코드와 설치 파일에서 제거했다.

처음 실행하는 사이트에서는 수집기 보안키를 한 번 입력할 수 있다. 보안키는 해당 사이트의 브라우저 로컬 저장소에만 보존하고 코드·문서·로그에는 기록하지 않는다.

## 완전수집 안전판

서버는 다음 조건을 모두 만족해야만 완전수집으로 확정한다.

1. 최신 검증 형식과 수집기 버전이 포함되어 있다.
2. 전체 또는 완전수집 범위다.
3. 예상 매물 수 이상을 실제 원본 ID로 확인했다.
4. 목록 수, 원본 ID 수, 처리 수가 일치한다.
5. 상세조회 실패와 주소·층 오류가 0건이다.
6. 페이지 잘림이나 안전중단이 없다.

하나라도 맞지 않으면 이미 저장된 결과는 보존하되 부분수집으로 기록한다. 부분수집은 기존 원본의 `missing_count`를 올리거나 매물을 숨기지 않는다.

## D1 사용량 최적화

- 원본 ID와 같은 주소의 통합 후보를 건별 쿼리가 아닌 묶음 쿼리로 조회한다.
- 사진은 URL별로 비교해 추가·삭제·순서변경 행만 쓴다.
- 연락처는 역할과 정규화 전화번호별로 비교해 달라진 행만 쓴다.
- 실제 변경이 없으면 `listing_history`를 추가하지 않는다.
- 네이버와 공실박스 저장 묶음은 세션별 고정 요청 ID로 중복 실행을 막는다.
- 공실박스는 목록을 매번 전수 확인하고 상세·연락처는 신규·변경 또는 마지막 상세확인 후 20시간이 지난 원본만 다시 읽는다.

## 사이트별 복구

- 네이버: 목록 비교는 2,500건, 저장은 응답속도에 따라 50~250건으로 자동조절한다.
- 당근: 브라우저별 작업 ID로 서로 다른 PC의 이어하기가 충돌하지 않는다. 상세 묶음은 10~50건으로 자동조절하고 일시 오류를 같은 묶음에서 최대 3회 확인한다.
- 공실박스: 300건 단위 목록 조회, 100~400건 단위 저장, 중단 지점 로컬 보존을 유지한다.

## 비용 영향

새 유료 서비스는 추가하지 않았다. 통합 로더와 수집기 파일은 기존 Cloudflare 정적 자산, API는 기존 Workers·D1·R2를 사용한다. 차등 저장과 묶음 조회로 기존보다 D1 행 쓰기와 쿼리 수가 줄어드는 구조다.
