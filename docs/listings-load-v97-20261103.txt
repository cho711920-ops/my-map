구현
기존에는 큰 목록도 헤더 준비+다운로드+본문 처리 합계 45초에 중단했다.
CSV/통합 원본 기본 읽기에만 초기 응답 준비 최대 90초, 이후 실제 바이트 수신 중 무진행 45초,
전체 최대 120초 제한을 적용했다. 작은 운영 읽기 15초와 명시된 custom timeout은 그대로다.
이는 정상 진행 중인 큰 응답과 R2의 원자적 cold snapshot 생성이 잘리는 경로를 고친 것이다.
서버 계산·전송량을 줄이는 속도 개선 또는 사용자의 실제 오류 원인 확정과 구분한다.
원본 JSON은 TransformStream으로 진행만 관찰하며 native json 소비를 유지하고 전체 문자열 복사본을 추가하지 않는다.
실제 수신 bytes가 없는 빈 chunk는 진행으로 인정하지 않는다. 실패 자료의 일부를 정상 목록으로 반영하지 않는다.
오류 안내에서 무조건 인터넷 문제라고 단정하던 문구를 시간초과·서버 상태·네트워크·응답 확인으로 구분했다.
LIST_TIMEOUT / LIST_HTTP_n / LIST_NETWORK / LIST_RESPONSE 코드만 표시하며 응답 원문이나 개인정보를 노출하지 않는다.
기존 단일 자동 재시도, 수동 재시도, 캐시 재검증, 원본 revision/proof, 계정 격리와 자료 보존 유지.
