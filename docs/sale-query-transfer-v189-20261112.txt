v189 건물/토지매매 기본 목록 전송 안정성

관찰과 한계
- 사용자는 건물/토지매매 LIST_HTTP_200/LIST_TIMEOUT 간헐 실패를 보고했다. 토지매매 재전환 후 목록 표시 성공을 직접 확인했다.
- 앞선 v187 Windows curl 건물기본 조회는 HTTP200 헤더3.42초 이후15초에 일부만 수신되었고, 동일 대형 응답 전체는35.248초/18,367,945decoded bytes에 도착했다. 브라우저 별도 실행4.934초 성공도 있었으므로 모든 실패 원인이 한 가지라는 증거가 아니다.
- 이번 수정 전 토지매매 실제 인증 조회는 헤더2.809초/전체3.332초/gzip493365 bytes/3476개 완전 JSON이었다. 새 사용자 요청 순간 로그의200/1.3~1.4초는 서버 응답 작업 시간이며 실제 브라우저 카드 표시 시간과 구분한다.
- 과거 상세 Cloudflare telemetry는403으로 조회할 수 없어 실패 요청의 실제 헤더/body 타임라인을 모두 확보했다고 주장하지 않는다.

수정
- 기존 검증된 snapshot range transport를 기본 건물/토지 query에 재사용한다. R2 현재 projection 원문을 스트리밍 gzip하고 revision+source ETag metadata로 별도 파생 저장한다. 현재원문 교체 시 게시하지 않는다. 압축파생본이 동일하면 재사용한다.
- manifest는 완전한 gzip 파일의 ETag/size/revision을 제공한다. 최대1MiB range3개 병렬, ETag/offset/length/실제바이트와 최종 gzip/JSON/기존 client exact propertyID proof를 검증한다. 부분 목록은 표시하지 않는다.
- 현재 revision 검증·인증은 기존 공개 bridge 경로다. 공개 요청으로 cache-wait 내부헤더를 전달할 수 없다. 구형client와 구형server 일반JSON 호환, 임대/delta/특수 필터/쓰기 경로 유지.
- null/ok:false HTTP200은 원래 본문과 responseStatus를 가진 DataResponseError로 보존한다. 실제 전송 보완과 별개이며 오류 문구 변경만 해결로 보고하지 않는다.
