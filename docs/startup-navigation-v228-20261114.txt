v228 새로고침·시장 전환 전송 경로 보완 (2026-11-14)

상태
공개 6de497c0-5277-42ac-a218-6550f2330416, 비공개 347577d3-72e1-4698-869d-3be6a54641b5 배포.
전체 1초 달성은 미완료다. 공통 검사의 통과와 실제 운영 지연 해소를 혼동하지 않는다.
최종 단일 공통 실행은 exit0이며 아래 검사/배포 대조도 완료했다. 속도 목표 미달과 구분한다.

확인한 문제와 변경
1. 초기 접속 확인을 인증 모듈 다운로드 후에 시작하던 순서를 HTML 파싱 시점으로 앞당긴다.
   현재 페이지에서 발생한 단일 응답만 인증 모듈이 소비한다. 최대 10초 유효성, 계정 확인,
   인증 전 개인 자료/앱 실행 금지는 유지한다. 인증 코드는 같은 deferred module로 HTML에 포함한다.
   읽기 전용 첫 화면 검증/표시 코드도 인증된 head template 내부에서 같은 순서로 실행한다.
2. 준비된 navigation도 건물 약 20,606행/39열, 원본 JSON 약 15.5MB였다.
   동일한 전체 행/조건/증명/사진 주소를 미리 gzip으로 준비한다. 저장된 gzip은 약 3.44MB다.
   기존 매분 준비 작업에 연결하며 예약 시간이나 수집기는 변경하지 않는다.
   원본 revision/ETag와 일치할 때만 파생 파일 및 제한된 완료 바이트 캐시를 쓴다.
   공개 HTTP/SW에는 개인 자료를 캐시하지 않는다. stream/promise를 요청 간 재사용하지 않는다.
3. 저장 자료가 있어 since를 보낸 뒤 변경 이력이 만료되면, 큰 optional 광고별 필터 자료까지
   전체 응답으로 돌아가던 경로를 수정한다. 변경 이력이 유효하면 기존 delta를 유지한다.
   이력이 만료되거나 delta 검증에 실패하면 전체 navigation으로 복구한다. 일부 목록을 전체로
   가장하지 않는다. 필터 자료의 후속 준비가 이미 표시된 전체 목록의 load 완료를 막지 않는다.
4. 다른 시장으로 전환하면 이전 시장의 foreground 조회와 큰 optional 필터 다운로드를 취소한다.
   같은 시장의 연속 필터 변경에서는 필요한 필터 준비를 유지한다. 이전 계정/저장 fence의
   응답은 적용하지 않는다. 인증 확인/화면 조회는 high, 공개 코드 미리 읽기/후속 자료는 low다.
5. 취소용 signal은 공통 data-access의 중복 조회 합치기를 우회한다. 그래서 동일 저장 fence의
   bulk 영수증 timer/batch-end 조회가 겹친 문제를 회귀 검사에서 발견했다. 계정/fence/완전한
   요청 조건이 같은 foreground promise는 한 번만 실행한다. 다른 조건/새 저장은 합치지 않는다.
6. PWA 갱신 확인이 window.load를 기다려 지도 SDK/사진 지연 때 늦어지던 경로를 DOM 준비
   이후로 옮긴다. 기존1초 지연, updateViaCache:none, 정상 waiting lifecycle을 유지한다.
   열려 있는 편집창 강제 reload/skipWaiting/clients.claim은 추가하지 않는다.

실제 운영 읽기 검수

  12카드/decoded 사진7. 반복 표본은 1706ms/1768ms로 여전히 1초 미달이다.

  후속 표본 중 인증 응답 준비 25초 이상, HTML 수신 37초 이상도 있었다.
  낮은 Worker wallTime만으로 사용자의 체감 지연이 해결됐다고 판단하지 않는다.
- 최신 변경 후 건물 재전환 목록 측정값 2715ms, 토지 목록 5346ms/실제 사진5420ms도 남았다.
  건물 첫 기본 12행은 원래 사진 없음인 항목들이므로 사진0을 사진 표시 성공으로 세지 않는다.
  건물 둔산동 클러스터 선택 후 실제 건물 사진 표시를 확인했다.
- 검수 브라우저는 LAX 경유 IAB다. 실제 사용자 Edge/휴대폰 결과를 시간대와 함께 대조해야 한다.
  통신망이 원인이라고 단정하거나, HTML 뒤 표시 시간만 전체 새로고침 시간으로 제시하지 않는다.

  목록2421ms(조회1438ms)였다. 최신 PWA 적용 후 기본 재방문은 목록2617ms/사진2829ms,
  인증준비2246ms였다. 이 값들을 실패 표본에서 제외하거나 1초 성공으로 세지 않는다.
- 일반 기본 주소의 query-startup hash8526c7b0d0d5dfe7 / PWA hash4768c60920cc0fce로
  새 실행본 전환을 확인했다. 상가 상세1/6→2/6 actual src 교체/complete/1500px 확인.
  검수용으로 연 IAB 탭은 전부 닫았다. 사용자 탭/캐시/로그인 자료는 지우지 않았다.
- 서버 저장/수집/예약/전원 설정을 시험 변경하지 않았다. 편집 저장·운영 원장 시험쓰기0.

남은 문제
모든 새로고침/최초 방문/시장 전환의 약1초 보장은 아직 검증되지 않았고 위 미달 사례가 있다.
첫 전체 자료가 없는 시장에서는 여전히 검증된 전체 navigation과 올바른 사진 주소가 필요하다.
20,606행의 JSON parse 122~138ms/decode147~245ms는 로컬 Node 참고값이며 운영 UI 측정값이 아니다.
큰 화면 투영의 반복 작업과 실제 전송/인증 지연을 추가로 나눠 검수해야 한다. 캐시를 임의 삭제한 최초 방문이나 운영 매물을 시험 변경한 검수는 하지 않았다. 준비된 건물 재전환2.4초를 캐시 없는 최초8초의 동일 조건 해결 증거로 쓰지 않는다.
원칙을 완화하거나 인증을 생략하거나 최근 자료/사진을 최신처럼 가장하는 해결은 허용하지 않는다.
