1. 업그레이드 복구의 자격을 예약enabled 대신 등록 유지+현재 실행 시장+
   현재 run 대상 여부로 판단. 수동 매매 target의 예약false는 그대로 보존.
   삭제된 대상/다른 시장을 새로 실행하지 않음. 기존 실패3회 한도 유지.
2. background가 시도별ID와 별개인 parent automationRunId를 provider에
   전달. 당근1.5.10은 모든 자동 요청에 같은 run ID를 전달/기존 checkpoint
   재개 때 ID 연결. 수동 실행은 빈 ID로 새 수집을 시작.
3. 서버는 job payload에 run ID를 보존. 같은 run·같은 URL·같은 거래유형·
   필터인 running/paused 시작 재요청은 기존 checkpoint 반환. 같은 조건의
   정상검증 완료는 기존 완료를 반환하여 자동 start가 목록0으로 초기화하지
   않게 함. 다음 독립 run ID/명시 수동/다른 필터는 새 회차 유지.
4. 완료 재사용은 completeCollection=true, 상태/phase complete, 주소 외
   실패0, 상세처리+기존동일=found, 전체목록 증명·최종수/마지막페이지·범위·
   빈목록 확인·기준시각·원본총수 조건을 모두 요구. 실제 실패/불완전한
   proof/다른 시장은 완료로 재사용 안 함. 광고 종료 판정 기준 변경 없음.
