# v220 필터 대기 보완 — 2026-11-13

## 원인과 변경

- 숫자·층·면적·수익률·분류 필터를 선택할 때 준비 중이던 전체 광고별 조건 자료가 컨트롤러 선택 토큰과 함께 버려졌다. 완료된 자료는 계정/거래시장/저장 fence/검증 revision이 같을 때만 보존한다. 대기 중인 같은 조건의 원격 조회는 로컬 결과로 교체하고, 늦은 응답의 토큰 검증은 유지한다.
- 운영에서는 상세 원장 한 건의 증거가 목록 스냅샷보다 새로워 자동 재조정되는 일이 있었다. 화면 표시를 위해 자동으로 편집용 원본을 읽던 경로가 전체 필터 자료를 폐기했다. 완전한 읽기 전용 카드 투영이 있는 경우 초기/목록 window/인접 카드 prefetch에서 편집용 원본을 자동 조회하지 않는다. 사진 주소 준비와 실제 이미지 preload/decode는 유지한다. 연락처·메모·수정·원본·선택 작업은 사용자가 요청할 때 정확한 원장 ID를 확인한다.
- 명시적 작업 중 더 최신인 원장이 들어오는 경우 원장 재조정 후 클릭 재실행이 사라지는 기존 경로도 보완했다. 사용자 행동만 재실행하며 수동 저장·같은 지번 이웃 변경은 하지 않는다.
- 비공개 조회기는 첫 숫자 필터에서도 현재 revision의 완전한 기본 광고별 투영을 재사용한다. 부족한 광고별 그룹/다른 시장/불일치 proof/지원하지 않는 범위는 원래 검증 조회로 돌아간다. 수집·DB·원본 광고·사용자 메모를 바꾸지 않는다.
- 기존 custom 캐시의 정확한 revision/조건 해시가 맞아도 새 준비 표시가 없던 응답을 호환 처리했다. 행·광고 조건은 그대로 두고 준비 신호만 추가하며, 별도 세 시장 회귀로 확인했다.
- 공개 서비스의 최초 revision 읽기와 비공개 조회를 병렬화했다. 최초/제공/최종 revision 동일성 검사는 유지한다. JSON delta에도 HTTP gzip을 적용하며 이미 인코딩된 범위 전송·사진 MIME은 중복 압축하지 않는다.
- 목록 및 실제 사진 decode 후 다음 프레임의 필터 처리시간을 DOM 진단값에만 기록한다. 원격 대기 후 로컬 재개 때 타이머를 초기화하지 않는다. 광고 ID/연락처/검색어를 서버로 전송하는 새 계측은 없다.

## 한계 — 완료로 확대 보고하지 않을 내용

- 캐시 없는 첫 건물/토지 진입에서는 각각 약 21.9/16.7초가 관찰됐다. 최종 실행본의 재방문은 저장 목록이 먼저 보였지만 최신 대조가 약 71.8초 걸린 표본도 있다. 명시적 상세 조회 뒤 전체 조건 해제도 최신 확인까지 7.9초 표본이 남았다. 저장 자료 표시와 최신 검증 완료는 다른 시간이다. 모든 새로고침/최초 방문의 약 1초 원칙은 아직 달성하지 못했다.
- 새 자료의 revision·저장 fence가 달라지거나 완전한 광고별 투영이 없으면 오래된 조건을 최신처럼 확정하지 않고 원격 검증을 한다. 이 기간의 첫 필터까지 항상 1초라고 보장하지 않는다.
- 원문에 의존하는 임의 업종/일반 키워드, 완료/찜 등 별도 범위는 투영으로 정확히 계산할 수 없으면 기존 원격 조회를 쓴다. 모든 필터 항목이 무조건 로컬로 계산된다고 보고하지 않는다.
- 버튼 줄·정렬·보류 색상·수집 예약·완료 판단·원장 데이터·전원 설정은 변경하지 않았다. 광고 누락을 이유로 거래완료 처리를 하지 않았다.
