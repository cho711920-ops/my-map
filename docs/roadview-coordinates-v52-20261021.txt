2026-10-21 로드뷰 좌표 준비 오류 보완 v52

범위/원인
- 사용자 목록 로드뷰 클릭 시 ‘이 매물의 지도 좌표가 아직 준비되지 않았습니다’ 오류 수정 요청.
- getItemCoordinates가 item.latlng 없으면 즉시 null로 반환해 저장 latitude/longitude가 있는 매물도 실패하는 경로 확인.
- 사진의 특정 원본/운영 인증 화면 직접 재현은 하지 않았음. 해당 코드 경로를 저장 좌표/미조회 좌표 시나리오로 재현해 수정.

구현
- 공통 좌표 읽기: SDK LatLng/직렬화 point, 저장 latitude/longitude 및 lat/lng 지원. 빈 값/0/비정상 범위는 제외.
- 좌표가 있으면 추가 조회 없이 기존 네이버 우선 거리뷰를 연다.
- 좌표가 없으면 기존 창에 조회중 표시. 기존 정확 지번 대조 함수를 재사용하고, 대전 도로명은 구/도로명/건물번호가 정확히 일치하는 단일 좌표만 채택.
- 동일 주소 진행 중 요청 공유. 8초 시간 초과/불일치/모호한 결과는 창 내부 안내. 건물명·인근 주소로 위치 추정하지 않음.
- 닫기/다른 매물 열기/주소 변경 이후 늦은 응답은 적용하지 않음. 대기 중 이전 네이버 화면은 숨긴다.
- 선택 매물의 메모리 latlng만 준비. 운영 DB/광고 주소·가격·확인·찜·원본·지도 필터/총건수 변경 및 전체 재정렬 없음.
- 목록/상세의 기존 공통 로드뷰 진입 함수 사용. 공통 좌표 읽기 개선으로 저장 좌표만 있는 내비·임장 호출도 지원.

- PC/모바일 브라우저 신규8, 기존 SDK재시도6, 주소확인14개 통과(중복 회차 제외).
