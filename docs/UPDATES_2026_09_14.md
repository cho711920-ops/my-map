# 2026-09-14 개선 후보 반영 기록

## 구현

- 초기 로딩: 부가기능도 병렬 미리받기 후 의존 순서대로 실행. JS/CSS는
  전역 함수명을 유지하며 압축하고, 모든 출력 HTML의 정적 자산 URL에 내용
  해시를 붙여 기존의 긴 브라우저 캐시와 충돌하지 않게 한다.
- 상세카드: 브라우저/서버 상세 캐시의 유효기간은 5분. 기존 화면을 우선
  표시하며 새 자료를 확인하고, 변경·목록 갱신·다른 카드 선택과 경쟁하는
  오래된 응답이 새 상태를 덮어쓰지 못하게 한다.
- 건축물대장: 기존 캐시를 표시하면서 일정 간격으로 재확인한다. 공공 API
  재조회 간격과 실패 후 재시도 간격을 분리해 반복 호출을 제한한다.
- PWA: 공개 정적 자산만 저장한다. API, 인증정보, 매물·고객·사진 응답,
  로그인/앱 HTML은 저장하지 않는다. 연결이 끊기면 개인정보 없는 일반
  안내만 표시한다. 작업 중 강제 새로고침이나 서비스워커 교체를 하지 않는다.
- 자동 품질 검사: CI에 ESLint와 TypeScript checkJs를 추가했다. lint는
  운영 JS·도구·수집기·테스트의 오류성 패턴을 검사한다. 기존 전역 스크립트
  구조 때문에 no-undef/no-unused-vars는 아직 적용하지 않는다. strict
  타입 검사는 층/호실 판정과 확인매물 메모 보존 모듈부터 적용했다.
  전체 레거시 코드를 TypeScript로 전환했다는 의미는 아니다.
- Vercel 정리: 구형 핸들러와 설정은 `legacy/vercel`에 보관하며 운영
  빌드에서는 제외한다. 공용 공공데이터 모듈은 Cloudflare 소스로 이동했다.
  Google 인증 라이브러리 11.0.2는 구형 핸들러 회귀검사용 개발 의존성이다.
  Cloudflare 운영 인증은 기존 Worker 구현을 사용한다.
- 수집 기록: 90일 초과 완료 원문 / 180일 초과 종료 세션을 소량씩 점검한다.
  최신 원문, 미완료·검수·보류 자료와 참조 중인 증거는 보존한다. 삭제는
  별도 R2 백업을 저장하고 다시 읽어 내용까지 검증한 뒤에만 수행한다.
  원본 매물·찜·메모·고객 데이터는 삭제하지 않는다.

## 운영 확인

- `js-map-media`의 `image-cache-7d` 규칙은 이미 활성화되어 있었다.
  `images/external/`만 7일 후 삭제하며, 전체 버킷 규칙을 덮어쓰지 않았다.
  새 수집 백업 `collector-retention/`은 사진 삭제 규칙 대상이 아니다.
- 2026-09-14 조회에서 90일 넘은 원문과 180일 넘은 세션은 모두 0건이었다.
  새 보관 정책은 현재 데이터를 대량 삭제하기 위한 것이 아니다.
- 월세 0원 후보 26건을 원본·이력·참조와 다시 대조했다. 최초 자동 판정은
  수정 0건이었으나 추가 원본 검수에서 공실박스 단일 반전세 1건의
  일치하는 증거를 확인했다. 원본 ID·주소·호실·거래조건·활성 상태가
  모두 일치하고 사용자 수정·대표보존·매매 충돌이 없는 경우만 허용하도록
  보정 도구를 강화해 해당 1건을 17,000/0 → 3,000/50으로 복구했다(만원).
  최신 D1 원문과 대표 필드를 재검사한 단일 매물 계획만 적용했으며
  연락처 2건과 원본·찜·메모 연결 보존, 이력 및 되돌리기 자료를 확인했다.
- 최종 정상 전세 6건, 공개 보류 19건이다. 공개 보류는 원본 없는 12건,
  당근 조건/거래 증거 확인 6건, 월세 협의로 금액을 확정할 수 없는
  공실박스 1건이다. 중첩된 과거 당근 원문의 거래정보도 읽도록 개선했지만
  비활성/혼합 거래를 자동 재공개하지 않는다. 대표값 보존 설정, 다른 공급자 충돌, 원본 미확인
  상태를 무시하고 가격·거래유형·대표매물·찜 연결을 바꾸지 않았다.
- 보류 매물의 가격/거래유형 확정에는 소유자가 확인한 원본 근거 또는
  처리 지시가 필요하다. 공개 보류를 임의 해제하지 않는다.

## 검증 명령

`pnpm run check`는 lint → strict 부분 타입 검사 → 전체 회귀 테스트 →
압축 정적 자산 빌드 및 Worker 배포 사전검증을 실행한다.

수집 보관 마이그레이션은 Worker 배포 전에 적용한다. 운영 기본 모드는
백업 검증을 전제로 한 `archive`이며, 환경변수를 `dry-run`으로 바꾸면
삭제 없이 후보 보고만 한다. Vercel 계정 해지나 Google 자료 삭제는
이 작업에 포함하지 않는다.
