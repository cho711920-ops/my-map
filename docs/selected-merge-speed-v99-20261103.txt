2026-11-03 선택매물 병합 및 병합·분리 반영 속도 v99

사용자 요청
- 체크한 매물들을 목록에서 한 번에 병합. 선택해제 오른쪽에 빨간 선택매물병합 버튼.
- 기존 상세의 병합·분리도 너무 느리므로 속도 개선 포함.

적용
- 매물 2~51개 체크 → 선택매물병합 → 남길 대표매물 선택 → 병합.
  거래유형·매매세부유형이 다른 선택, 저장 중인 메모·미저장 메모, 중복/누락 대표ID 차단.
  사진·광고 내용은 첫 화면 진입이나 버튼 렌더에서 선조회하지 않는다.
- 동일 엔드포인트의 selectedMerge 플래그에만 새 일괄 경로 적용.
  선택 전체의 원본광고·미디어·연락처를 한 번의 D1 batch로 이동하고 나머지 대표만 soft-delete.
  서로 다른 조건은 원본마다 보존. 직접등록 중 원본이 없는 카드는 내부 원본 스냅샷으로 보존.
  선택한 운영메모를 중복 제거 후 합침. 출처 광고를 거래완료/미노출 처리하지 않음.
- 선택·개인기록 버전 비교와 요청 영수증을 같은 트랜잭션에 기록.
  동시 변경/도중 실패는 전체 롤백. 동일 요청번호 재시도는 완료 영수증 반환.
  응답 실패 시 mutationStatus를 읽어 확인하고 자동 POST 재송신하지 않음.
  요청 계정 검증 및 accepted POST의 처리/캐시 무효화를 waitUntil로 유지.
- 찜·임장 폴더의 대상 키만 대표 public ID로 치환하며 폴더명·메모·나머지 항목 보존.
  현재 기기의 로컬 편집은 기존 saveLists/충돌 조정 경로로 연결.
  개인 대표사진은 계정별로 남길 대표의 기존 기록(명시적 초기화 포함) 우선.
  대표 기록이 없을 때만 병합 매물의 사진 메타데이터를 상속하고 기존 R2 파일은 유지.
  상속 사진 조회의 assetPropertyId는 같은 계정의 원래 파일 위치를 사용.
  상가임대와 매매를 서로 병합하지 않음.

속도 개선의 근거와 범위
- 기존 병합/분리 저장 후 전체 CSV와 전체 원본 연결정보를 다시 받았음.
  최근 읽기 점검에서 각각 약87.8MB/57.3MB 규모였으며 사용자 체감 지연의 가능한 경로다.
  사용자 기기의 실제 요청·저장·화면 반영 시간을 직접 측정한 수치는 아니다.
- 변경된 대표 public ID를 저장 응답에 포함. 저장 직후 listingOriginals만 요청하며
  대표 조건과 원본 inventory/proof를 함께 검증한 후 반영한다. 50개 단위, 최대51개.
  분리로 생긴 대표 삽입과 없어진 대표 제거를 지원하고 나머지 카드는 유지한다.
- 이전 전체 조회는 generation fence로 취소하고 IDB 초기 캐시는 성공 직후 동기적으로 무효화.
  proof 불일치·동시 메모 편집·늦은 응답 시 최신 반영 완료라고 안내하지 않는다.
  기존 상세 병합/원본 이동/분리에도 같은 범위 갱신을 적용.
  구 버전 저장 응답에 affectedPropertyIds가 없는 경우 기존 전체 갱신 fallback 유지.
- 전체 데이터 리비전을 임의로 최신으로 올리지 않는다. 다른 수집/변경을 놓치지 않도록
  기존 1분 폴링과 필요 시 전체 갱신 정책은 유지. 모든 전체 다운로드를 제거한 것은 아님.
- 운영현황 집계·그 캐시 정리를 저장 응답 대기에서 분리.
  목록·원본·상세 캐시 삭제는 병합/분리 성공 응답 전에 계속 기다린다.
  정상 작업의 체감 개선 방식이며 특정 초 이내 완료를 보장하는 실측 결과는 아니다.
