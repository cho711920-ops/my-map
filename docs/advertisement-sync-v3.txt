JS부동산 광고번호 동기화 변경 - 2026-10-14

원칙
- 출처+원본 광고번호+거래유형으로 저장한다. 대표매물/찜/메모 식별값은 유지한다.
- 기존 연결은 유지한다. 확실한 동일매물만 통합하고 애매하면 즉시 별도로 게시한다.
- 정상·동일 범위/필터의 전체목록이 검증된 뒤 한 번 빠진 원본만 미노출 후보로 숨긴다.
- 실제 계약완료와 원본 광고 미노출을 구별한다. 재등장 광고는 다시 반영한다.
- 살아 있는 원본이 하나라도 있으면 대표매물은 유지한다. 사라진 대표조건은 활성 원본으로 교체하되 실제 사용자 수정 필드는 보존한다.

초기 적용/과거 자료
- 새 범위의 첫 검증은 관측된 광고의 비교 기준을 만든다. 기존 자료의 과거 필터를 추측해서 일괄 완료 처리하지 않는다.
- 과거 병합 검증대기는 awaiting_source_refresh로 증거를 보존한다. 다음 수집에서 다시 관측된 광고번호는 상세를 새로 읽어 검증대기 없이 게시한다.
- 이 변경이 기존의 미확인 광고 전부를 즉시 정리했다고 말하면 안 된다. 오래된 범위 미기록 광고는 새 전체목록 비교의 근거가 없으므로 별도 원본 확인이 필요하다.

수집 완전성
- 네이버: 원본 총건수/최종 고유번호/마지막 페이지/실제 지역·필터 일치. 반복/빈 중간페이지/커서 누락/필터변경은 종료판정 금지.
- 당근: 실제 선택 clusterId+propertyFilter의 커서 체인. 구 이름만 보고 행정구 전체라고 주장하지 않는다. 제외된 거래유형과 원본 전체 관측수를 구별한다.
- 공실박스: 동일 bounds+zoom+btype+검색필터 해시. 실제 선택 번호가 지도 circle 전체 합집합과 일치해야 한다. 작은 목록/0건도 실제 성공 응답·합집합 증거가 있어야 한다.
- 공실박스 자동화는 현재 화면 최대클러스터를 선택한다. 다중 클러스터 지도 전체를 자동 수집하는 기능을 구현했다고 말하면 안 된다. 전체 합집합이 증명되지 않으면 관측 광고만 저장하고 종료판정은 보류한다. 추측한 bidxs로 전체목록을 합성하지 않는다.
- 오래된 수집 응답/재전송/동시 저장은 timestamp·CAS로 최신 상태를 덮어쓰지 않는다.

층/호실
- 공실박스 Ff=-1,Ho=B03은 지하1층 B03호로 보존한다. 원본의 명시된 층이 우선이다.
- 숫자 최소/최대 층 범위에서는 미확인 층도 포함한다. 보증금/월세/평수/출처/찜 등 다른 조건은 모두 충족해야 한다.
- 실제 수동 호실 수정은 보존한다. 표시 전용 층/호실 보정은 기존 찜의 레거시 room 키를 바꾸지 않는다.

성능/복구
- 필터 전환마다 서버 조회를 추가하지 않는다. compact 원본 메타를 사용하며 raw 개인정보는 클라이언트에 전달하지 않는다.
- 확장 업데이트 버전이 달라져도 같은 날 예약수집을 중복 시작하지 않는다. 기존 미완료 이어가기와 명시적인 수동 재실행은 유지한다.
- 수동 수정 이력 부분 인덱스를 추가한다. 전체 94k 응답의 운영 성능은 별도 실측 대상이며, 표본 warm 수치로 전체 속도 향상을 단정하지 않는다.
- 변경 전 코드 zip/Git bundle/실행파일/수집 설정/전체 D1 SQL 및 복원 검증은 외부 백업 폴더에 보존한다.
- 데이터 복원과 코드 롤백은 별개다. 코드만 되돌려도 DB는 돌아가지 않는다. 전체 DB 복원은 이후 새 메모/찜 등 쓰기를 잃을 수 있으므로 수집 중지·쓰기 검토 후 실행한다.
- 추가된 predeploy-review-state.json은 이번 마이그레이션에서 바꾼 검증대기 상태·결과·시각을 보존한다. 이미 새로 게시된 광고를 무조건 옛 대기로 되돌리면 안 된다.

보류
- 광고자/중개사/세입자 정보 표시 추가는 이번 범위에 포함하지 않는다.
- 지도 공급자 변경, 디자인 재편, 강제 재수집, 광고 일괄 완료 처리는 하지 않는다.
