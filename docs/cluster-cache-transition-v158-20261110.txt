2026-11-10 확대·이동 직후 클러스터 전환의 기존 캐시 대기 v158

신고
엣지·크롬·스마트폰 공통, 확대/축소/지도 이동 직후 다른 클러스터를 누르면 이전 목록이 약3초 남는다.
지도를 켜 두고 충분히 기다린 뒤에는 목록이 빠르게 바뀐다.

재현한 원인
v157은 새로운 cardProjectionV157 표시가 있는 조회 패킷만 원장 응답 전에 그리도록 했다.
기존 버전에서 저장한 version152 completeQuery 캐시는 정상 복원됐지만 이 표시와 사진 스칼라3개가 없다.
그 상태에서 확대/이동으로 아직 원장을 읽지 않은 구간을 선택하면 prepareList가 다시 상세 응답을 기다렸다.
처음 화면/이미 방문한 구간은 캐시 원장이 준비되어 빨랐다. 새 전체 조회가 끝난 뒤에도 빨라진다.
새 형식 캐시만 사용한 v157 운영 검수는 이 경로를 확인하지 못했다.
사용자 브라우저 캐시를 직접 추출한 결론은 아니며, 실제 코드에서 같은 현상을 재현한 경로다.

변경
기존 형식도 계정/조회 범위/완전한 query/원장ID·출처 proof가 검증된 읽기 전용 행이면 조건을 먼저 표시한다.
사진 항목이 없다는 이유로 목록 전체를 상세 응답 뒤까지 보류하지 않는다.
사진 주소가 없는 기존 캐시는 사진 없음으로 속이지 않고 기존의 사진 확인 상태를 유지한다.
사진이 이미 준비된 새 패킷/원장은 기존 실제 썸네일/사진 DOM 경로를 사용한다.
정확 원장이 준비되기 전에는 수정·저장·상세 동작을 실행하지 않는 보호를 유지한다.
원장 연결·쓰기 CAS·메모/조건/계정 캐시 무효화·운영 데이터·수집기에는 변경이 없다.

화면 표시 검수
기존 계측은 showList가 DOM을 만든 시각이었다. 실제 화면에 그려질 기회를 따로 확인한다.
숫자/행정 클릭 시작부터 측정하며 두 animation frame 뒤, 마지막 클릭 의도와 실제 표시 ID가 일치할 때만 기록한다.
이전 클러스터의 늦은 프레임은 새 클릭의 완료로 기록할 수 없다. 판정은 데이터 준비/HTTP 완료와 구분한다.

회귀 검사
실제 IDB에 구형 패킷을 저장한 뒤 재접속, 최신 전체 query와 새 원장 응답을 모두 고의로 지연한다.
실제 지도 idle 경로로 확대6→5→4→6/중심 변경 후 클러스터40→60→80→40을 선택한다.
수정 전 PC·폰 모두 이전 FIXTURE 목록이 남아 실패. 수정 후 매번 새 ID 목록/표시 프레임이 응답 전에 준비된다.
준비 전 수정창/상세 차단, 해제 후 정확 매물의 월90/실제 사진 decode/원장ID·금액 보존도 확인한다.
최종 전체 검사·배포·운영 검수 수치는 CODEX_HANDOFF.md 맨 위와 outputs/v158-*를 확인한다.

한계
기존 캐시에 없는 사진을 네트워크 없이 새로 만들 수는 없다. 사진 확인 상태를 무대기 달성으로 보고하지 않는다.
이번 완료 범위는 기존 캐시에서 상세 응답이 다음 클러스터 목록을 막던 경로다.
최초 새로고침/최신 전체 query 전송의 모든 대기 또는 사용자 물리 기기 전체를0초로 보장하지 않는다.
기존 원 버튼 복구a81ba6ad와 이후 메모·찜·조건·사진·수집 예약은 보존한다.
