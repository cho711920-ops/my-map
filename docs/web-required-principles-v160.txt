JS부동산 웹 필수 원칙 — 모든 기능 수정에 적용

1. 상가임대·건물매매·토지매매 모두 새로 열기/새로고침 후 약 1초 내외에 실제 매물 목록과 올바른 사진이 함께 보여야 한다. 첫 방문과 저장 자료 있는 재방문을 따로 측정한다.
2. 지도를 확대·축소·이동하면 해당 범위의 클러스터가 즉시 보여야 한다.
3. 클러스터를 연속으로 선택해도 선택한 매물 목록과 실제 사진이 바로 바뀌어야 한다.
4. 상세카드의 첫 사진과 다음 사진이 빈 화면·이전 사진·번호만 바뀐 상태로 멈추면 안 된다.
5. 메모·금액·층수·연락처·조건·확인/미확인/보류 등 모든 수정 작업은 클릭/저장 후 약1초 안에 의미 있는 화면 변경을 표시한다. 서버 미확정 값은 저장 중으로 구분하고, 서버 확정 후 새로고침에도 보존한다. 실패/충돌 시 해당 ID만 되돌리고 입력·선택을 보존한다.
6. 수정 대상은 사용자가 선택한 원장 ID다. 주소·층·대표 광고·행번호로 다른 원장을 추정해 덮어쓰지 않는다.
7. 상가임대·건물매매·토지매매 모두 필터 적용 즉시 조건에 맞는 목록·실제 사진·클러스터가 표시돼야 한다. 첫 적용·연속 변경·조건 해제를 같은 기준으로 검수하고, 빈 목록의 장기 조회·이전 조건의 잔류를 통과로 세지 않는다.
8. 원본 분리·원본1개 이동·대표전체/선택 병합·거래완료도 전체 조회나 서버 후속 정리를 기다려 화면을 막지 않는다. 임시 표시 ID는 원장/연락처/사진 조회·저장 대상으로 전송하거나 실제 원장 캐시에 넣지 않는다. 저장 결과가 늦어도 다른 계정·다른 원장의 입력을 덮어쓰지 않는다.

검수
- pnpm run check에는 pnpm run test:principles가 포함된다. 테스트를 누락하거나 지연 상한을 올려 통과시키지 않는다.
- query-startup-v152: 새로고침 조건부 검증/변경분의 완전한 ID·정렬 검증, 전체 상세 응답 차단 중 첫 카드·실제 사진,
  확대·축소·이동 및 구형 IDB+연속 클러스터 선택, 사진 decode, 저장·새로고침/서로 다른 ID 보존, 보류 왕복 변경.
- query-first-frame-v160: 가상 목록에 다음 창이 붙어도 검증된 첫 창 사진만 선표시. 인증 전 공용 코드 준비와 사적 데이터 차단.
- 기존 사진1→2/편집 커서·한국어 조합/메모 추가/권리금·월세·지하층·전화/서버 경합 검사를 계속 유지한다.
- 제어 환경의 클러스터 목록 표시기회250ms, 사진 decode 후 표시기회500ms는 회귀 탐지 상한이다.
  이 숫자를 운영 웹의 '항상0초' 보장으로 바꾸어 말하지 않는다. 운영에서 첫 방문/저장 자료 있는 재방문을 나눠 실제 표시도 확인한다.
- 로딩 문구 숨김, 완료 광고의 잠깐 재노출, 오래된 사진·조건을 최신처럼 재생하거나 사진 없는 카드를 사진 성공으로 세는 방식은 금지한다.
- 로그인·통신·HTML 수신·코드 준비·인덱스 검증·원장 준비·실제 사진 표시를 분리해 기록한다. 도구 호출 시간이 다운로드 시간은 아니다.
- 운영 매물에 검수용 값을 저장하지 않는다. 쓰기 검수는 격리 자료에서 수행하고, 배포 파일은 cf:verify로 실제 바이트를 확인한다.
- 아직 못 맞춘 원칙은 미완료로 명시하고, 한 사례나 준비된 사진의 빠른 재표시를 전체 달성으로 보고하지 않는다.

- v217: 캐시 없는 세 시장도 큰 광고별 필터 전송을 보류한 상태에서 완전한 navigation/실제 사진 첫 표시를 검수한다. navigation rows·순서·total·원본 proof를 잘라 전체 완료로 가장하지 않는다. 필터 catalog는 동일 계정/시장/fence/revision/전체 rows 검증 뒤 합친다.
