- 광고번호별 상태, 사진, 찜, 메모, 수동 호실, 계약완료 표시와 화면 성능을 보존한다.

원인과 변경
1. 전체 CSV와 전체 원본은 별개 요청이다. 수집 중 한 건만 갱신돼도 전체 버전이
   달라져, 내용이 같은 다른 매물까지 원본 연결을 거부할 수 있었다.
2. CSV와 원본에 매물별 SHA-256 연결키를 추가한다. 부모 ID/version/수정시각/상태와
   실제 읽은 공개 원본의 ID·출처·원본번호·활성·누락·내용해시·확인시각·미노출 상태를
   같은 순서로 증명한다. 전체 버전이 달라도 그 매물의 키가 정확히 같은 경우만 연결한다.
3. 원본의 키는 실제 응답 행에서 만든다. 페이지 사이 부모가 바뀌거나 최종 원본수와
   다르거나 수동 필드 조회 도중 부모가 변경되면 해당 키를 발행하지 않는다.
   뒤늦게 읽은 새 증명을 오래된 응답에 붙이지 않는다. 원본0개도 명시적으로 검증한다.
4. 불일치 매물만 캐시 없는 listingOriginals 조회로 재확인한다. public/internal ID를
   명시적으로 매핑하며, 정상인 다른 사진·후보는 유지한다. 같은 전체 버전이라는 이유로
   매물별 불일치를 우회하는 경로(수동 재조회 포함)는 허용하지 않는다.
5. 한 번에50개, 순차 최대200개만 조회한다. 진전이 있으면 다음1분 확인에서 이어가고,
   진전 없는 오류는 기존60초 간격/최대3회 자동복구 제한을 유지한다. 사용자 재조회 가능.
6. 새 조회 세대·수동 편집으로 바뀐 행은 늦은 응답으로 교체하지 않는다. 메모·완료 저장이
   요청 시작 전부터 진행 중인 경우에도 요청/응답 양쪽에서 제외해 동일 객체를 보존한다.
7. 새 상세로 확인된 자료보다 오래된 전체 응답, 확인시각 퇴행, 같은 시각의 활성 반전은
   거절한다. 알려진 원본 삭제는 캐시 없는 부분조회에서만 확정한다.
8. 모든 현재 행의 키가 원본과 일치할 때만 정상 초기 캐시를 저장한다. 전체 버전을
   임의로 바꿔 붙이지 않는다. 전체 캐시는 CSV v3-source-proof / 원본 v14-source-proof로
   분리하고, 복구 도구의 캐시 대상도 갱신했다(도구 실행·삭제는 하지 않음).

영향과 한계
- DB migration, 광고 완료/후보 일괄 변경, 매물/사진/찜/메모 삭제 없음.
