원인
query 선표시 카드 capture click이 전화 버튼까지 guardIds에 넣어, 전화번호만 볼 때에도 listingOriginals(쓰기 원장·연결 원본·사진 정보)를 기다렸다.
전체 원장 응답 차단 상태에서 수정 전 코드를 다시 실행하면 번호가 표시되지 않는 실패를 재현했다(outputs/v171-before-corrected-phone.log).
기존의 이미 준비된 원장 팝업은 빠른 표본도 있었다. 모든 번호 조회의 지연을 같은 원인이라고 단정하지 않는다.

변경
기존 인증/비저장 unifiedListingContacts 액션에 card=171을 추가했다. 정확 공개 property_id로 작은 원장 연락처 projection을 읽고, 내부 listing.id로 연결 연락처/기존 수동수정 이력을 조회한다.
원본광고 raw JSON·사진·가격 원본을 읽거나 반환하지 않는다. 같은 sourceSnapshotKey를 읽기 전후 재확인하며 저장·수집 중 자료가 바뀌면 409로 거부한다. 공개차단/다른 ID/계정 불일치도 거부한다.
같은 extractListContactsV650로 수동 필드·역할 메모·건물 공통/개별 예외를 판정한다. 중개사 광고번호를 임대인으로 추정하지 않는다. 건물 설정은 기존 cache/loadTask로 합류한다.
사용한 버튼만 pointerenter/focus/pointerdown/click 준비한다. 계정/저장 fence/정확ID/proof별 메모리 cache 최대24개·30초와 진행 요청 합류. 초기 전체 번호 preload, 사적 번호 영구cache, 추가 폴링 없음.
query 원장·쓰기 cache 설치 없음. 선표시 카드에 과거 linked contact cache를 적용하던 경로도 차단했다. 창 token·계정·fence·목록 의도 검증으로 다른 매물/닫힌 창/재열기 뒤 늦은 결과를 차단한다.
이미 준비된 원장의 수동번호는 연결 원본 조회보다 먼저 표시한다. 연결 결과 뒤에는 현재 수동·공통번호를 다시 판정한다. 실패를 번호 없음 성공으로 캐시하지 않는다.
