JS부동산 v225 — 수정 화면 선반영과 정확한 저장 확정
2026-11-13 / 운영 배포 및 최종 공통 검수 완료 / 최초 준비 1초의 남은 미달 유지

사용자 기준
- 메모·조건·상태·원본 이동/분리/병합 등 모든 수정은 클릭 후 약1초 내 의미 있는 화면 반응.
- 서버 저장 확정과 미확정 화면 초안을 구분. 실패 시 해당 원장만 복구하고 입력·선택 보존.
- 기존 새로고침·필터·지도·클러스터·실제사진 기준과 정확 원장 ID 원칙을 유지.

실제 원인과 변경
1. 요약 목록에서 상태 버튼까지 상세 원장 전체 준비를 기다렸다. 보류/확인/미확인/완료는 인증 계정+정확 ID+기존 상태 CAS로 보내고, 화면 상태를 먼저 표시한다. 연속 클릭 전체에 공통인 최대3개 요청 제한을 적용하고 전체 검증을 병합한다. 대기 중인 새 매물도 화면은 먼저 변경한다.
2. 목록의 실제 표시 원본은 query navigation인데 이전 optimistic 코드는 allItems만 고쳤다. 조회 요약과 이미 준비된 상세 카드에 동일한 pending 상태·조건 미리보기를 적용한다. 실제 원장과 미확정 복제본을 분리한다.
3. 원본 이동·분리·대표전체 통합은 전체 조회에 막혔고 reconcile은 새 분리 ID를 목록에 추가하지 않았다. 저장 ACK에 검증된 영향 원장 inventory를 포함하고, 추가/삭제/기존 원장을 정확하게 대조해 즉시 재구성한다. 전역 조회와 IDB 삭제는 화면 표시를 막지 않는다.
4. 임시 분리 카드가 예전 visible-original recovery로 넘어가 실재하지 않는 ID를 조회했다. 임시 카드를 복구·수정 대상에서 배제하고 폐기 뒤 늦은 카드 콜백도 차단한다. 임시 ID는 원장 캐시/서버 쓰기에 들어가지 않는다.
5. 원본1개/전체 이동의 대상 카드·체크박스는 상세 hydration을 건너뛰되, 사용자가 클릭한 ID를 고정한다. 안내 배너가 그 대상 체크박스 클릭을 가로막지 않게 했다.
6. 최신 전체 조회가 늦을 때 연속 상태 수정은 마지막으로 확정된 상태를 다음 CAS 기준으로 쓴다. 다음 변경 실패 시 이미 저장된 이전 상태까지 되돌리지 않는다.
7. 분리 전 선택된 클러스터와 새 분리 카드 선택은 저장 후 실제 원장 ID로 연결한다. 실패 시 기존 source 선택으로 복구하며 다른 지번 선택을 바꾸지 않는다.
8. 늦은 원본 저장 ACK는 해당 원장의 상세만 무효화한다. 그사이 연 다른 매물의 사진2나 새 원본 이동 안내를 닫지 않는다.
9. 요약 선택 병합은 서버에서 원본 proof를 재검증하며 같은 D1 batch의 precondition에도 포함한다. source-only 수집 경합도 잘못된 병합을 허용하지 않는다. 같은 requestId의 proof/대상이 바뀐 재시도는 거절한다.
