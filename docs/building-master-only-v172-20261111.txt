같은 건물로 묶기: 마스터 계정 전용 v172 / 2026-11-11

범위
사용자 이미지의 '같은 건물로 묶기'와 기존 묶음의 관리·해제 작업을 마스터에게만 표시/허용한다.
일반 다중선택, 선택 개수, 매물 체크, 연락처·건물 공통 임대인 기능은 유지한다.

서버
기존 ALLOWED_EMAILS의 첫 bootstrap 마스터와 실제 인증된 user.email을 비교한다. role=owner/admin만으로는 허용하지 않는다. 마스터 구성 누락도 거부한다.
기존 계정별 buildingRegistryV164 읽기에 canManageBuildingGroupsV172를 추가한다. 일반 계정에게 buildings 정보는 반환하지 않고 contacts와 CAS version은 유지한다.
일반 계정이 nonempty buildings를 직접 또는 enqueueMutation으로 보내면 mutation 예약 전403으로 거부한다. saveCloudState 내부에서도 확인한다.
일반 계정의 연락처 전용 저장에서는 이미 있던 숨긴 buildings를 서버에서 다시 읽어 보존한다. 기대 version과 기존 CAS를 적용하므로 오래된 저장이 다른 변경을 지우지 않는다.
새 테이블·데이터 이관·운영 자료 변경 없음. 기존 계정별 소유권과 기대 계정 검증을 유지한다.

화면
권한은 기존 작은 설정 읽기의 서버 응답으로 확인한다. 별도 권한 요청/추가 폴링/목록·사진 조회 차단 없음.
일반 계정·확인 전에는 묶기/관리 버튼이 없고 openGroup 직접 호출도 창을 열지 않는다. 묶음 지도 적용도 하지 않는다.
계정이 바뀌면 권한을 즉시 초기화한다. 권한 회수 응답은 오래된 자료 version이어도 즉시 반영하고 열린 묶음 검토창을 닫는다. 실제 선택과 저장된 자료는 변경하지 않는다.
localStorage의 과거 그룹과 가짜 권한으로 마스터 UI를 복원하지 않는다. 기존 공통 연락처 UI/원장 ID/메모·금액·사진은 유지한다.

검수
SQLite API: 실제 마스터 허용, 다른 owner/admin/member/viewer 읽기 숨김과 직접·큐 요청403, 구성 누락 거부, 거부 시 운영 행/예약 행 불변, 일반 계정 공통 연락처 저장 중 hidden buildings 보존·경합 거부.
PC·폰: 일반 계정 묶기/관리/직접 호출 차단, 공통 연락처 유지, 마스터 검토 가능, 오래된 버전의 권한 회수와 계정 전환 후 UI 제거, 원래 선택·저장 자료 불변.
기존 원칙 전체 검수와 실제 배포 확인은 CODEX_HANDOFF.md 기록을 참조한다. 운영 검수용 건물/연락처를 저장하지 않는다.
