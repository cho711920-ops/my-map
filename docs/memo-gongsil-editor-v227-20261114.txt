v227 메모 열기·공실박스 연락처 수정 입력 연결 (2026-11-14)

사용자 신고
- 메모 열기/수정창이 3초 이상 기다림. 전부 전화번호가 자동 기입되지 않는다고 신고.
- 사용자는 메모의 명시 번호뿐 아니라 공실박스에서 자동 수집되어 연락처 창에 이미 있는 번호도 수정창에 기입할 것을 명확히 요청했다.

확인한 원인
- 운영 최신 v226에서도 실제 메모 첫 열기 1742ms를 재현했다. 구버전 잔류만으로 설명하지 않는다.
- 요약 카드의 메모 버튼이 전체 listingOriginals/사진·연결 광고 hydrate를 선행했다.
- 메모 역할 자동 기입은 extractMemoRoleContacts만 사용했다. 공실박스 listing_contacts는 연락처 팝업용 별도 투영으로, 편집 폼에는 전달하지 않았다. 연락처 조회 완료=편집칸 기입 완료라는 이전 검수 가정이 잘못됐다.

구현
- 읽기 메모는 exact-ID listingChanges 한 행 + 현재 source proof 검증으로 읽는다. bounded64 private memo 캐시는 account/fence/원장ID/proof 별도 키로 저장하며 로그인 경계에서 제거한다. read-only 메모 투영은 writable master나 전체 광고 inventory로 승격하지 않는다.
- 메모가 그려진 뒤 명시적으로 연 원장 하나만 기존 전체 검증 경로로 준비하고 검증된 원장 캐시를 checkpoint한다. 메모/조건 쓰기 exact-ID/CAS/원본 proof는 유지한다.
- 공실박스 구조화 연락처와 메모의 명시 역할을 편집 자동 기입에 함께 사용한다. 명시 메모의 임대인/주인·세입자를 우선하며 기존 직접 기입/직접 지움/건물공통 readonly 값을 보호한다.
- 공실박스의 임/주를 우선, 그 공급처에서 임대인측으로 분류한 가족/남성/여성/관리는 후순위 참조한다. 부동산·불명 역할은 임대인/임차인으로 추정하지 않는다. 같은 표현이라도 일반 광고/메모의 사장·사모·관리만으로 소유관계를 추정하지 않는다. 명시 '임대인(사모)'·'세입자(사장)'는 두 역할을 유지한다.
- query의 검증된 unifiedListingContacts card171 한 건/동일 진행 promise를 연락처 팝업·편집창에서 공유한다. 무거운 사진/전체 목록·전체 건물 조회를 추가하지 않는다. 늦은 연락처는 계정/fence/수정세션/대상 원장/충돌/저장 상태를 확인하며 입력 중인 번호를 덮어쓰지 않는다. 열기·취소는 쓰지 않는다.
- 운영 원장 시험쓰기/수집기/예약/전원/D1 migration/고정 rollback 변경 없음.
