2026-11-06 사용자 원칙 검수 후 보완 v124

사용자 필수 원칙
- 새로고침 시 매물 목록과 사진 즉시 표시.
- 상세카드 다음 사진 무대기.
- 수정한 메모/조건 즉시 반영 및 새로고침 후 보존.
- 동일 지번이어도 다른 원장에 덮어쓰지 않음.
문구를 숨기거나 오래된 조건을 새 자료라고 표시하는 것은 해결이 아님.

변경
1. 인증 성공 뒤 초기 목록 캐시 스크립트를 data-access 바로 다음/카카오 SDK 이전에 실행.
   전체 IndexedDB 읽기를 SDK 준비와 겹치고 최초 read가 같은 Promise/객체를 한 번 소비.
   scope/epoch/patch version/유효기간/전체성 검사를 유지. 확정 수정/구조 변경/쓰기 뒤
   예열 결과는 폐기. 계정 승인 전에 자료를 보여주거나 새 데이터 저장소를 만들지 않음.
   필수 본문 스크립트 preload도 SDK 준비와 겹치되 실행 순서/실패 재시도/앱 격리 유지.
2. 아직 다운로드/디코딩 중인 인접 사진도 그 Image 노드 자체를 상세/확대에 인계.
   같은 src 재지정 방지. 전환 완료/실패 이벤트는 인계된 노드에 연결.
   이전 프레임 유지, 빠른 연속 선택/닫기/원본 분리/실패 복구/절약 모드 보존.
   교체된 분리 노드의 src와 핸들러 해제. 기존 최대4개/400만픽셀 한도 유지.
   전체 사진을 새로 받거나 서버/매물/광고/사진 원본/수집기/전원 설정을 변경하지 않음.
3. 비내용성 숫자 진단: 캐시 읽기 소요, 첫 카드 DOM 준비 시각, 선택 사진 준비 소요.
   사진 준비 시간은 로더 내부 계측이며 사용자 단말의 클릭부터 전체 표시까지와 동일하지 않음.

검증
- 전체 Node 2047/2047, lint/typecheck/build/Worker dry-run 통과.
- 최종 PC/휴대폰 핵심22/22 + 기존 사진/메모/권리금/확정수정/범위48/48.
  새 pending 사진 최종 반복6/6. 이전 코드 비교2/2: 기존 samePendingNode=false,
  변경 후 true/소스 재지정0. 이것이 기존에 매번 파일이 재다운로드됐다는 증거는 아님
  (브라우저는 서로 다른 Image 요청도 합칠 수 있음).
- 처음 광범위 실행은 로컬 Node OOM/CSPRNG/worker 종료로 중단. 그 도중 별도
  브라우저 기준 비교를 같은 output 디렉터리로 실행한 검증 구성도 잘못되어,
  최종은 출력 경로를 분리하고 순차 작은 묶음으로 재검증. 전체 광범위 무실패 주장 금지.
- 초기 새 검사에서 이전에 인계된 분리 Image src가 남는 것을 발견해 해제 추가 후
  연속 선택/닫기 최종 통과. 기준 비교의 불필요한 src 재지정을 추측한 assertion은
  실제 기준 코드 관측0에 맞춰 제거했으며 same-node 비교 및 새 코드0 검사는 유지.
