문제와 변경
v118은 첫 썸네일과 장수만 먼저 받고 개별 광고 사진 목록을 추가 조회했다. 이 조회가 실패/지연하면 다음 사진 불러오는 중 대기가 남았다. 사용자 원래 인증 HTTP 장애의 직접 원인은 미포착이며, 이번 변경은 정상 초기 메타데이터를 받은 뒤 추가 목록 조회에 의존하지 않도록 한다.
초기/범위 메타데이터의 기존 40개 필드 뒤 photoPathsV119를 추가했다. 첫 thumbnail과 나머지 URL 공통 접두어 길이/접미어를 저장한다. 실제 사진 바이트를 전부 미리 받는 기능은 아니다. 목록/정렬은 전체 URL을 해독하지 않고 상세에서 선택한 광고만 해독한다. 기존 열려 있는 대기 갤러리에 같은 source proof의 새 사진 경로를 적용하고, 늦은 개별 목록 응답이 현재 페이지를 되돌리지 않도록 한다. 기존 v118 메모/조건 캐시 영수증 패치 유지.
정확 source_id+listing_id의 현 공개원본만 사용. 주소 기반 대체 없음. 공실박스는 신뢰 Photos만 사용. D1 운영자료/대표/가격/메모/찜/상태/수집 변경 없음.

250개 원장씩 미디어 경로 조회/직렬화하고 직렬화한 그룹은 해제한다. SQLite가 공개정책 OR로 전체 과거 source를 재검색하던 초기 신규 쿼리는 검증 도중 실제 D1 429/7429 과부하를 발생시켰고, 배포 전에 json_each CROSS JOIN/단항 + 조건으로 원장/미디어 인덱스 탐색으로 수정했다. 새 배치 예:2392 source/약3만 rows read/74ms. 이는 사용자 최초 장애의 직접 원인이라고 단정하지 않는다.
