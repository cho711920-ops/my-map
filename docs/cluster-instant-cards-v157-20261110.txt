2026-11-10 클러스터 목록과 편집 원장 준비 분리 v157

문제
v156은 첫 조회를4/6개로 줄였지만, 그 원장과 원본 사진 주소 응답을 기다린 뒤 목록을 표시했다.
따라서 실제 운영 첫 클러스터 선택에서1.5~3.1초 대기가 남았다. 무대기 요구를 충족한 것으로 보지 않는다.

변경
인증된 조회 인덱스의 실제 대표 조건과 대표 사진 주소1개로 첫 카드를 즉시 표시한다.
대표 광고ID·사진 건수·썸네일만 추가하고, 메모·연락처·전체 사진 목록은 인덱스에 싣지 않는다.
알 수 없는 사진 건수를0으로 바꾸지 않는다. 조건 필터로 선택된 광고의 사진과 가격을 함께 사용한다.
완전한 원장·전체 사진 주소 준비는 기존 제한된 배치로 병행한다. 준비된 사진 DOM은 동일 출처일 때 보존한다.
읽기 전용 카드는 allItems나 완성 원장 캐시로 승격하지 않는다. 첫 새로고침의 인증·조회 전송 대기는 별도다.

정확한 수정과 경합 보호
먼저 표시된 카드의 동작은 정확한 원장ID와 proof 검증이 끝난 후 실제 카드에서만 실행한다.
새 클러스터·필터·계정으로 이동하면 늦게 완료된 이전 카드 동작을 취소한다.
동일 목록의 단순 갱신은 선택 의도를 바꾸지 않는다. 실제 목록 구성·순서가 바뀔 때만 의도 세대를 갱신한다.
동 이름표 선택은 처음부터 해당 동 전체를 사용한다. 화면 안 일부를 먼저 띄운 뒤 동 전체로 바꿔 행 순서와 클릭 의도가 흔들리는 경로를 제거했다.
동 전체 필터링 시작부터 첫 카드 DOM 표시까지 계측하며, 필터 계산을 계측 밖으로 빼지 않는다.
서로 겹치는 배경 준비/명시 동작은 진행 중 원장 조회를 공유하고, 남은 ID만 새 문맥으로 읽는다.
수정·메모 저장의 CAS·영수증·불변 원장ID 검증과 수집기/운영 데이터는 변경하지 않는다.
메모 작성 중에는 검증된 실제 원장으로 카드 정보만 갱신하고 textarea/한국어 조합/커서를 유지한다.

검수
숫자·행정 클러스터, PC·폰에서 선택된 모든 원장 응답을 막고도 정확한 첫 카드와 실제 사진 decode 확인.
원장 미보유 동안 수정창 미실행, 해제 후 정확한 원장 수정창 또는 상세 열림, 사진 노드 보존 확인.
이전 가상 스크롤 구간과 먼 구간, 늦은 이전 클러스터 동작 취소, 겹친 원장 조회의 게시 경합 포함.
필터된 대표 광고의 가격·사진ID 일치, 사진 건수 불명 보존, 잘못된 사진 투영 거부 검사 포함.
최종 전체 검사·운영 배포·실측은 CODEX_HANDOFF.md 맨 위와 outputs/v157-*를 확인한다.

배포와 보존
준비된 조회 결과의 R2 캐시 키를 v157로 바꾼다. 원본 thin 메타데이터/CSV 형식은 그대로다.
비공개 조회 Worker를 먼저, 공개 UI를 다음으로 배포한다. 구형 패킷은 기존 엄격한 원장 준비 경로로 처리한다.
기존 D1/R2만 사용한다. 새 DB·마이그레이션·수집 강제 실행·운영 매물 검수용 저장 없음.
원 버튼 복구는 원래 a81ba6ad에 고정하며 이후 메모·찜·조건·사진은 보존한다.
항상 모든 통신/사진이0초, 모든 미래 오류 해결, 초기 새로고침 무대기 전체 달성을 주장하지 않는다.
읽기 전용 운영 패킷13365행의 직렬화 비교: JSON8.38MB/gzip2.23MB, 새 사진3항목 제외 시6.68MB/1.55MB.
이는 같은 자료의 크기 비교이며 브라우저 전송 벤치마크가 아니다. 최초 자료 전송·준비 시간과 클러스터 클릭 시간은 별도로 측정한다.
