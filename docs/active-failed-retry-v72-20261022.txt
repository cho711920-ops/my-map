실패 재실행 버튼 비활성화 보완 — 2026-10-22 v72 / 확장 1.1.24

사용자 문제
- 당근 실패 수정(v71) 후 실패 재수집 버튼을 누르려는데 비활성화.
- UI는 runState.active 하나로 모든 시장의 6개 실행 버튼과 확인 버튼을 잠금.
  네이버 retry_wait도 active이므로 당근 실패 재실행이 불가능했음.
- 실행기 역시 같은 실행에 이미 있던 실패 대상은 completedKeys/reportKeys에
  들어 있다는 이유로 다시 대기열에 추가하지 않았음. UI만 풀어서는 해결 안 됨.
- 앞서 사용자에게 실패 재수집을 누르라고 안내할 때 이 잠금을 확인하지 못한
  안내 오류가 있었음. 버튼/실행기 둘 다 보완.

동작
- 동일 거래유형 + 동일 runId의 실패·부분완료 재수집만 active 중 허용.
  전체/임의 선택/다른 시장 실행은 잠금 유지.
- 사용자 확인 뒤 서버가 아니라 확장 실행기에서 최신 실패 기록을 재확인.
  완료·진행 중·자동 재시도 대기 지역은 이 동작의 재실행 대상에서 제외.
- 재시도 대기(phase=retry-wait,currentTabId=null)면 선택한 실패 지역부터
  바로 시작. 원래 대기 대상은 그 뒤에 남기고 cursor/체크포인트와 기존 retryAt,
  pendingSaveRetryAtV56를 보존. 만료 전 원래 저장을 재전송하지 않음.
- 실제 수집 중이면 현재 tab/index/targetRunId를 유지하고 실패 대상만 뒤에 추가.
  두 수집을 병렬 실행하거나 현재 지역의 창을 닫지 않음.
- 선택된 공급처의 circuit만 해제, 그 공급처의 선택하지 않은 실패는 자동으로
  재실행하지 않음. 새 오류가 나면 기존 공급처 차단·유한 재시도 적용 유지.
- 이전 실패는 previousAttempt에 보존하고 현재 항목을 pending으로 변경.
  이미 재등록한 pending/running 대상은 연속 클릭해도 추가하지 않음.
- 원본 매물·찜·메모·임장·수집 시간 설정·선택 시장을 변경하지 않음.

업데이트
- background/autorun/options/manifest 빌드를 1.1.24로 일치시킴.
- 설정창 새로고침 시 이전 worker라도 실제 수집 탭 없는 재시도 대기이며
  다음 예약 시각이 10초 이상 남았을 때만 자동 업데이트 적용 가능.
  실제 탭 있음/알람 만료·미확인/설정 편집 중에는 자동 reload 안 함.
- 업데이트 후에도 기존 대기 대상의 최초 재시도 예정 시각을 유지하고,
  대기 중 적용이었다면 설정창을 다시 엶.
