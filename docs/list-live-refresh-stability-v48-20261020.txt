확인한 원인

- 최초 로컬 전체 캐시를 먼저 표시한 뒤 최신 CSV로 바꾸는 경로는 isAuto=false라 위치 보존 대상에서 빠졌다.
- 소량 변경분 적용 경로도 현재 읽기 상태를 저장/복원하지 않았다. 원본 메타정보 보완 경로는 보존 처리가 있었지만 위 행 번호 문제의 영향을 받았다.
- 1분 리비전 확인, 보이는 매물의 원본 정보 보완, 캐시에서 최신 전체 자료로 교체하는 경로를 구분해 검수했다.

수정
- 읽기 앵커는 기존 작업 키를 우선 사용하고, 행 번호가 바뀌었을 때 고유 propertyId가 하나뿐인 경우에만 같은 매물을 찾는다. 기존 작업 키/동일 주소 별도 호실의 식별 정책은 변경하지 않았다.
- 읽던 카드가 제외된 경우 다음 남아 있는 카드, 렌더된 구간 전체가 제외된 경우 기존 순번에 가까운 남은 매물로 이어서 보여 준다. 종료/삭제된 매물을 화면에 고정해 두지 않는다.
- 캐시→최신 전체 자료, 자동 전체 갱신, 소량 변경, 원본 메타정보 보완에서 갱신 직전 읽기 상태를 보존한다. 네트워크/좌표 준비를 기다리는 동안 사용자가 스크롤하면 응답 적용 직전의 위치를 기준으로 한다.
- 작업 체크도 단일 고유 매물에 한해 새 행 번호에 연결하며, 제외된 매물의 체크 건수는 정리한다. 모호한 중복 매물에 체크를 임의 이전하지 않는다.
- 새 휠/터치 입력 이후에 이전 위치를 복원하는 지연 프레임을 추가하지 않았다. 명시적으로 다른 검색/거래유형/목록을 선택하는 동작은 기존 전환 정책 유지.
- 실제 매물 수는 계속 최신 자료로 계산한다. 자동수집/광고별 노출 정책/찜/운영 매물 데이터 변경 없음. 자동수집 브라우저나 확장 재시작 없음.
