변경
- 같은 계정·필터·저장 영수증 세대의 완전한 읽기 전용 query 캐시로 조건부 조회한다. 현재 revision이 같으면 전체 packet을 다시 받지 않는다.
- 완전한 변경 이력이 있을 때만 최대1024 변경 ID의 정식 조회 행/제외 ID/전체 정렬·행번호를 받는다. 클라이언트는 base revision·필드·전체 ID 집합·중복·own proof·완전한 순서를 검사한 뒤 게시한다. 이력 누락/불완전 응답/구형 필드는 기존 전체 조회로 돌아간다. 조건·출처·대표 선택 규칙은 기존 canonical query와 동일하다.
- 조건부 읽기의 현재 revision은 비공개 서비스에서 읽고 공개 bridge가 게시 직전 다시 검증한다. 동일 revision의 불필요한 순차 R2 확인을 줄였으며 계정 인증/최종 변경 확인을 생략하지 않았다.
- 검증된 query 조건·사진은 전체 쓰기 원장을 기다리지 않고 먼저 표시한다. 실제 편집은 정확-ID 원장·proof/CAS 확인 후만 수행한다. 새 point가 더 최신이면 per-property로 표시하고 전체 최신 인증으로 속이지 않는다.
- IDB 읽기 유한 경계/늦은 응답 무효화. 첫 창 cache capture가 다음 가상 창까지 포함해 검증 자료 없는 카드 때문에 전체 거부되던 사례를 재현했다. 저장된 검증 point의 카드만 선표시한다. 원문·메모·초안/실행 속성·쓰기 권한을 캐시 HTML로 복원하지 않는다.
- 공용 첫 화면 JS 다운로드를 인증과 겹치되 실제 실행·데이터 읽기는 기존 인증 이후다. 거부 세션의 공용 코드 선다운로드/비실행/사적 데이터 미조회 검사를 추가했다.
- 지도 이동 시 이전 구간의 미사용 배경 사진 요청을 한꺼번에 무효화한 뒤 취소한다. 취소 중 대기 중인 옛 사진을 새로 시작하는 회귀를 수정 전 실패/후 통과로 확인했다. 표시 중 Image는 유지하며 계정/proof/원본ID/URL 경계와 요청·메모리 제한을 유지한다.
- 보류/확인/미확인은 기존 listings.status의 명시적인 관리 상태이며 계약완료와 별개다. 선택한 property ID의 state 필드만 updateProperty CAS로 저장한다. 메모·조건·다른 ID를 덮어쓰지 않는다. 부분 실패는 성공 건을 되돌리지 않고 실패 선택만 유지한다. 저장 후 기기 캐시 실패가 서버 저장을 취소한 것처럼 보이지 않게 한다. 계정 변경 후 늦은 영수증은 새 계정 캐시/선택을 갱신하지 않는다.
- PC·폰 선택 메뉴에 임장완료→보류→미확인. 보류를 확인으로 바꿀 때는 임장완료, 미확인으로 바꿀 때는 미확인 버튼. 수정창에도 확인매물/미확인 매물/보류 옵션이 있다. 명시 상태가 오래된 메모 표식보다 우선한다.
- 활성 매물이 모두 보류면 주황색. 보류와 다른 상태가 섞이면 기존 색에 주황 보류 개수 표시/tooltip을 더해 전체가 보류인 것처럼 보이지 않는다. 완료 묶음 회색은 유지한다.
- 원본 폴더와 실제 checkout AGENTS.md, docs/web-required-principles-v160.txt에 필수 원칙을 명시했다. test:principles에 query-first-frame-v160을 추가했다. 기존 CI push/PR의 test:browser에도 자동 포함된다. 제어 환경 목록 paint250ms/사진 표시500ms 회귀 상한을 임의 완화/제외하지 말 것. 운영 전체 0초 인증 값과 혼동하지 않는다.
