# 2026-09-18 당근 주소 확인 보류

## 확인한 문제

원본의 정확한 번지는 비공개이고 동 이름만 제공됐는데, 광고 설명의 `소형상가 12평`과 `문창동 1층`을 각각 `소형상가 12`, `문창동 1`이라는 지번으로 오인했다. 두 원본의 층수·면적을 주소로 사용한 파서 오류이며, 9월 18일 속도 변경 배포 전 생성된 자료다.

## 운영 처리

- 사용자가 승인한 두 매물만 `daangn_exact_address_unproven` 공개 보류로 전환했다.
- 원본, 매물 내용, 사진, 연락처, 메모, 찜 및 고객 연결을 삭제하거나 주소를 추정 수정하지 않았다.
- 매물/원본 ID, 버전, 수정시각, 원문, 원본 개수와 기존 보류 유무를 확인하는 조건부 SQL로 처리했다. 보류와 감사 이력을 각각 2개 추가하고 매물 버전만 증가시켰다.
- 운영 → 공개 보류 검수함에 `당근 정확한 지번 미제공 · 주소 확인 보류`로 표시한다. 거래가격 근거만으로 주소 보류를 해제할 수 없다.
- 원문 주소 보류 건수/자동수집 보고서는 사후 조작하지 않았다. 이 화면은 기존 매물의 공개 보류와 구분된다.
- 조회 캐시만 무효화했다. 원본/이미지 파일은 보존했다. 기존 주소 오류 팝업이 남으면 전체 새로고침으로 다시 확인한다.
- 로컬 비공개 작업 기록과 조건부 원복 SQL: `.wrangler/private/address-hold-2026-09-18/`. 원복 SQL은 실행하지 않았다.

## 재발 방지

- 당근의 지번 판별에서 층·면적·금액을 번지로 잘라 사용하지 않는다.
- 광고 설명은 전체가 주소 형태인 경우만 후보로 인정하며, 정상 구조화 지번을 우선한다.
- 현재 원문에 정확한 지번이 없다는 근거가 있으면 과거 목록/저장값의 잘못된 주소를 재사용하지 않는다. 정규화, 목록 병합, 저장 단계 모두에 적용한다.
- 숨김 공개 좌표가 이전 값으로 다시 채워지지 않도록 한다. 공급처가 별도로 제공한 직접 좌표와 정상 지번 처리, 네이버/공실박스 처리 방식은 유지한다.

정확한 번지가 원본에 공개되거나 별도 검수 근거가 확인될 때까지 두 매물의 공개를 보류한다. 비공개 번지를 추측해 지도에 표시하지 않는다.

## 검증

- 전체 로컬 회귀검사 867/867, ESLint, 타입 검사, 정적 자산 빌드 및 Worker 배포 dry-run 통과.
- 신규 주소 검사 40개에 실제 두 원본, 괄호 단위, 금액 쉼표, 정상 건물명 괄호, 구조화 주소, 이전 잘못된 값 재사용 차단을 포함한다.
- 공개 보류 표시/민감정보 비노출/가격 근거만으로 보류 해제 차단을 검증했다.
- 조건부 전환 SQL의 정상 실행·원복 및 버전/원문/원본 개수 충돌 시 차단을 메모리 SQLite에서 검증했다. 운영 재조회에서 보류 2건, 감사 이력 2건, 일반 공개 조회 포함 0건을 확인했다.
